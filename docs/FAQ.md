# 常见问题

## 必须连接相同 Wi-Fi 名称吗？

不必。手机连 5GHz、盒子连 2.4GHz 或有线均可，前提是同一可互通 IPv4 子网。
检查访客网络、客户端隔离和跨频段多播转发；相同 SSID 也不能保证设备互通。

## 搜索不到设备

确认电视首页显示“独立 DLNA 已就绪”，手机发送端支持 DLNA，并选择首页显示的完整设备名。
iPhone 要允许发送端 App 访问“本地网络”。检查路由器隔离、多播过滤、VPN 和防火墙。
“网络已连接”不代表投屏服务就绪，也不保证路由器允许发现。

## 为什么 B 站 / YouTube / AirPlay 列表里没有？

标准 DLNA 不等于平台官方投屏、Google Cast 或 AirPlay。
当前不实现这些专用入口，也不保证所有版本的发送端 App 都显示标准 DLNA 设备。
YouTube 网页链接不是直接可播放的视频地址。

## 连接了但打不开视频

检查视频是否需 Cookie、特殊请求头、DRM 或特殊编解码器。
盒子使用 Android 系统播放器；较老固件的 TLS、HLS 和编码支持有限。
临时鉴权链接可能过期。视频打开超过约 20 秒未准备完成会报错，先尝试普通 MP4。

## 字幕 / 快进没效果

外部字幕需由发送端提供 SRT / VTT 地址；应用不自动搜索字幕。
内嵌字幕取决于固件；直播或未知时长流可能不可 Seek。

## 默认桌面不能设置

由厂商系统决定。请保留原桌面，通过系统提供的默认应用设置选择。
本软件不会 Root、刷机、强行替换或禁用原桌面。

## Wi-Fi 名称显示不出来

部分 Android 系统要求位置权限和系统位置开关才能读取 SSID。
首页菜单可以自愿授权；本应用不调用定位 API。拒绝时仍可以投屏。

## 是否安全、是否开源？

仅在可信家庭网络使用。本版没有 PIN / 配对，同一子网设备能控制播放。
不提供账号、广告、统计 SDK 或自建云中转；不应映射接收端口到公网。
应用源码已按 MIT 许可证开源，见 [`cast-launcher`](../cast-launcher) 和 [构建说明](BUILD.md)。
开源不改变网络安全边界，也不代表所有设备或发送端都已验证。
